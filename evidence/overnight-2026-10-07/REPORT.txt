VOICEBEAM LAB: MEASURED COMPONENTS AND BUILD
7 October 2026 | baseline VoiceBeam 0c848260 | host CPU only

DECISION
Use Moonshine Tiny int8 for the accuracy-focused lab, Silero v5 probability VAD, TitaNet Small with longer, frozen enrolment, raw audio for ASR and GTCRN for headphone monitoring. Keep MediaPipe tracking; LR-ASD was not ported. Do not claim overlapping voices are isolated. No component is established as universally best and nothing was tested on an iQOO.

ASR RESULTS: MICRO-AVERAGED WORD ERROR RATE
Lower is better. Reference normalization: lowercase, punctuation removed; digits kept. Same references for all arms, no tuning of weights. 30 deterministic NPTEL Pure-Set Indian-English lecture clips, 12 noisy variants, 15 held-out LibriSpeech speaker clips, 6 synthetic equal-energy overlaps. 9 additional LibriSpeech clips used ONLY for enrolment. Total 72 fixtures / 582.75 s; 63 ASR evaluation clips.

Arm                         Indian clean  +10 dB noise  LibriSpeech  overlap
Current Zipformer 20M          69.98%        88.89%        18.22%     125.29%
Bigger streaming Zipformer     48.79%        71.93%         1.86%     126.44%
Moonshine Tiny, whole clip     25.17%        43.27%         4.46%     145.98%
Moonshine, new lab wrapper     26.93%        48.54%         6.69%     142.53%

Wrapper: neural speech probability, 1 s pre-roll, re-decode every 2 s, 600 ms silence endpoint, 12 s maximum utterance. This is chunked offline recognition, NOT a native streaming ASR. Median first hypothesis is 2.0 s of audio on each scenario in this harness. Audio timeline delay is not phone wall-clock caption latency. Whole-clip Moonshine is an accuracy ceiling, not the shipped timing behavior.

Serial host speed on six clean clips, one CPU thread:
Current RTF 0.0250; bigger 0.0640; Moonshine 0.0183. RTF is inference time/audio duration. CPU-only batch throughput is not live latency, thermal behavior, or concurrent camera+audio performance. Main evaluation arms ran independently in parallel; their speed values are not used as phone comparisons.

Paired bootstrap on 30 Indian-clean clips (2000 draws, seed 20261007): bigger model WER improvement 95% interval 12.31 to 30.38 percentage points; Moonshine 37.53 to 52.29 points vs current. This quantifies clip-set sampling only, not generalization or ground-truth uncertainty.

VAD RESULTS
12 source clips, inserted 1 s zero padding; controlled pure noise/hum cases.
The energy gate flags 100% of white-noise and hum frames as speech. Silero flags 0% of both, at the fixed 0.5 threshold. Both flag 0% of pure silence.

Speech-clip frame-positive fraction (NOT recall):
Energy clean 81.3%, noisy 98.9%; Silero probability clean 54.6%, noisy 51.7%.
There are no human within-clip speech-boundary labels, so these cannot be called precision/recall or false-negative rates. First detection from inserted clip boundary: energy clean 21 ms/noisy 9 ms; Silero clean 107 ms/noisy 683 ms. The clip boundary is not an exact speech onset. Preserve pre-roll; the neural VAD rejects noise but can delay or miss soft speech. This is a tradeoff, not proof it wins every case.

SPEAKER VERIFICATION
Three LibriSpeech test-clean speakers, five held-out utterances per speaker. For each query: 1 genuine and 2 impostor comparisons, 15 genuine/30 impostor decisions. No speaker-identity ground truth for NPTEL, so no Indian-English speaker verification claim. Verification-table threshold held fixed at cosine 0.425 (the baseline 0.5 remapped score), not optimized on test data. Clean enrolment uses 3 separate snippets; current protocol 1.5 s each, long protocol 3 s each. Query length also changes from 1.5 to 3 s, so enrolment and query-length effects are confounded.

Model       clean FAR/FRR 1.5 s   noisy FAR/FRR 1.5 s   clean FAR/FRR 3 s   noisy FAR/FRR 3 s
CAM++          30% / 0%             40% / 20%            100% / 0%           100% / 0%
ResNet34       56.7% / 0%           66.7% / 20%           66.7% / 0%          66.7% / 6.7%
TitaNet Small   0% / 0%              0% / 20%              0% / 0%             0% / 0%
ERes2Net en     0% / 20%             0% / 53.3%            0% / 0%             0% / 13.3%

FAR = impostor accepted fraction; FRR = genuine rejected fraction. Zero observed errors on 30 impostor trials does not establish a zero population error rate. Very small and narrow sample. Runtime state decisions require score >0.8 (cosine >0.53), stricter than the table threshold; this runtime behavior is not the quoted FAR/FRR result. Longer CAM++ inputs inflate similarities for both genuine and impostor voices here, so longer alone is NOT a reliable fix.

Baseline code already averaged 3 embeddings and fed speech-gated frames. Those are not new improvements. Lab changes: 3 s windows, 9 s total enrolment, 0.75 lip-confidence requirement, partial enrolment reset when confirmation disappears, no self-confirming online adaptation. Android voice path is denoised; host verification used clean and synthetic noisy inputs without GTCRN. This end-to-end mismatch requires phone/denoised follow-up. Camera-free mode stays disabled.

DENOISE
12 additive white-noise clips at 10 dB: mean SI-SDR input 9.99 dB, output 18.18 dB. Cross-correlation alignment is used for enhancement metric only. This is speech enhancement, not speaker separation.
Moonshine clean WER after GTCRN 29.58% vs 25.17% raw; noisy 50.88% vs 43.27% raw. Current Zipformer barely improves on noise (87.72% vs 88.89%). Keep GTCRN for listening, not ASR. Metrics use offline GTCRN API; Android uses its streaming API, so listener quality on the phone remains unverified.

OVERLAP AND FACE TRACKING
All ASR arms fail on equal-energy overlaps when scored against just the target transcript. WER above 100% is possible from insertions. This is a target-only objective, not an all-speaker transcription benchmark. No target-extraction model was installed, so no speaker-separation improvement is claimed. Scalar gain scales both simultaneous voices equally and cannot improve their target/interferer ratio. Speaker-aware state logic can reduce turn-taking leakage, not recover an isolated source.
LR-ASD: published audio-visual model, but no Android port or runtime test completed. MediaPipe position tracking remains; face ID swaps, camera motion, stale visual cues, and audiovisual synchronization still need phone/video tests. Do not call active-speaker detection benchmarked.

WHAT WAS IMPLEMENTED
- Moonshine Tiny int8 chunked captions; 1 s pre-roll, 2 s decode cadence, bounded utterances.
- Silero v5 probability in the monitor/voice pipeline and ASR worker.
- TitaNet Small speaker embedding, longer frozen enrolment.
- TargetState names UNLOCKED/TARGET/OTHER/UNCERTAIN/OVERLAP; strong other-speaker visual evidence vetoes false voice match. Overlap is explicitly ambiguous.
- Capture timestamp/probability/voice flag travels with caption queue packets. Dropped blocks no longer compress the caption timeline. Full per-word timestamps are not implemented.
- Separate com.akashrajeev.voicebeam.lab install, display name VoiceBeam Lab.
- No executable Actions workflow in lab snapshot. No main merge/public change. Lab signing key is not committed.

VERIFICATION
Kotlin code compiled and 20 JVM unit tests passed, including existing 16 tests and 4 new tests for visual veto, overlap, utterance bounds/pre-roll and timestamp gaps. Final test recheck completed successfully after tightening enrolment. Android emulator/device, native model loading, app startup, rendered UI, recording/export and end-to-end live captions NOT tested. This is code-complete lab work, not a verified Android release.
APK attempts: local Java 17, Android SDK 35 and build tools installed; several builds stopped at dex merging from memory exhaustion in the 2 GB host. Do not provide an APK unless an actual later local build succeeds. No Actions minutes spent.

NEXT TESTS THAT CHANGE THE DECISION
1. Run new lab on the iQOO/headphones: startup, first caption/end-caption delay, 10 min continuous camera+audio, heat/battery/queue drops.
2. Indian-English and Malayalam-accent speakers, including Akash: disjoint enrolment and test sessions, background and off-camera impostors, overlap. Calibrate threshold on separate development speakers, then test held-out speakers.
3. Speech-boundary labels on quiet, accented, distant speech: Silero recall/onset vs energy, threshold and pre-roll tuning only on development clips.
4. Real visual/audio synchronized video with known speaking faces: wrong-target caption fraction, ID swaps, offscreen cases, lag and turn-taking leakage.
5. Listening test for denoise: clipping, loudness, feedback protection, missed syllables and perceived quality. No loudspeaker monitoring.
6. If instant captions matter more than accuracy, expose the bigger streaming Zipformer as a separate arm, not an untested hybrid default.
